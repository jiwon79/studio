# Runway Walk

최종 작품은 `/runway-walk/angle.html`이다. `/runway-walk/`도 같은 작품으로 이동한다. 좌우 드래그로 −90°부터 +90°까지 5° 단위로 방향을 바꾼다. 방향키도 5°씩 움직이고 Home은 정면, Space는 재생·정지다. 선택한 방향을 브라우저에 저장한다.

## 최종 사진

`assets/quality/`의 투명 WebP 2,972장만 재생한다. 내장 GPT 이미지 도구와 Higgsfield의 GPT Image로 화질·누끼를 보정한 결과다. 원본 비교 옵션, 과거 크롭/색상 시안, 12장 자세 보정 실험, 실험 비교 페이지와 원본 아틀라스는 제거했다. 생성 사진은 얼굴·신발·옷감의 세부 형태가 달라질 수 있다.

`manifest.json`은 재생 사진·해시·출처 제공자·원본 프레이밍을 복원하는 전체 배율/이동을 연결한다. `provenance.json`은 생성 프롬프트·원본 출처·생성 해시를 보관하며 런타임 JS에 포함하지 않는다. 네이티브 생성 결과와 작업 영수증은 Git 제외 캐시에 보존한다. 과거 파일은 Git 이력에서도 확인할 수 있다.

`angles.json`의 원본 아틀라스 번호와 타일 위치는 프레임 식별 및 원본 추출 도구의 메타데이터다. 작품은 원본 아틀라스를 요청하지 않는다. `quality-originals.json`은 과거 생성 거절 사진의 제외 목록이며 원본 재생 예외가 아니다. 일정과 드래그 예비 후보 모두 최종 보정 사진만 선택한다.

## 재생

`reference-schedule.json`이 각도별 300틱의 사진 순서를 정한다. 25fps로 같은 착장을 3프레임씩 표시한다. `reference-sequencer.ts`는 가져온 Quaternius `Walk_Formal_Loop`의 보행 위상과 원본 관절 데이터로 순서 및 방향 전환을 선택한다. `photo-registration.ts`는 사진 전체의 크기·회전·이동만 적용한다. 관절 교환이나 팔다리 변형은 하지 않는다. 모델 파일의 라이선스와 출처는 `media/reference/`에 남긴다.

초기에 37개 각도의 보정 사진 전체를 다운로드한 뒤 첫 9개 재생 구간을 디코딩한다. 마지막 사진과 재생 준비가 끝나기 전에는 작품을 표시하지 않는다. 로딩 화면은 사진 수·백분율·수신 용량·구간 준비 수와 실패 시 재시도를 제공한다. `quality-library.ts`는 압축 사진을 재사용하고 현재·다음 재생 구간만 디코딩한다. 방향 전환 중에는 기존 시계를 유지하며 준비된 새 각도를 현재 보행 시점에 연결한다.

HTML은 `no-store`, 이미지와 JS는 콘텐츠 해시로 캐시한다. 링크에 `v=`를 붙일 필요가 없다.

## 유지보수

- `pnpm test pages/runway-walk scripts/runway-walk`: 재생·로딩·사진 무결성·전환 회귀 검사.
- `pnpm typecheck`, `pnpm build`: 타입 검사와 배포 파일 생성.
- `node scripts/runway-walk/check-motion.mjs`: 37개 각도를 각각 1,200틱 측정한다. 기존 발·몸·얼굴·출현 구간 및 전환 진행 기준을 유지한다.
- 새 사진/일정은 위 수치 검사와 실제 재생 검토를 모두 거친다. 수치 통과만으로 시각적으로 자연스럽다고 판정하지 않는다.

영상 출처와 원본 추출 설정은 `scripts/runway-walk/angle-sources.json`, `angle-shots.json`에 있다. 현재 작품과 관계없는 초기 합성·생성 배치·검토 서버 코드는 정리했다. 자세/각도 생성 실험을 다시 시작하려면 최종 작품과 분리한다.
