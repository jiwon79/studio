# Runway Walk

최종 작품은 `/runway-walk/angle.html`이다. `/runway-walk/`도 같은 작품으로 이동한다. 좌우 드래그로 −90°부터 +90°까지 5° 단위로 방향을 바꾼다. 방향키도 5°씩 움직이고 Home은 정면, Space는 재생·정지다. 선택한 방향을 브라우저에 저장한다.

## 최종 사진

기본값은 최종 보정 사진 2,972장이다. lil-gui의 `사진 비교 → 사진`에서 `보정 전`과 `보정 후`를 선택한다. `재생`을 끄면 같은 프레임을 고정해서 비교할 수 있다. 기본 인코딩은 `assets/quality-avif/`(전체 이미지 약 79.0MiB)이며, AVIF 디코딩을 지원하지 않는 브라우저에는 `assets/quality/`의 WebP를 제공한다. 내장 GPT 이미지 도구와 Higgsfield의 GPT Image로 화질·누끼를 보정한 결과다. 과거 크롭/색상 시안, 12장 자세 보정 실험, 실험 비교 페이지와 원본 아틀라스는 제거한 상태다. 생성 사진은 얼굴·신발·옷감의 세부 형태가 달라질 수 있다.

`manifest.json`은 재생 사진·해시·출처 제공자·원본 프레이밍을 복원하는 전체 배율/이동을 연결한다. `provenance.json`은 생성 프롬프트·원본 출처·생성 해시를 보관하며 런타임 JS에 포함하지 않는다. 네이티브 생성 결과와 작업 영수증은 Git 제외 캐시에 보존한다. 과거 파일은 Git 이력에서도 확인할 수 있다.

`angles.json`의 원본 아틀라스 번호와 타일 위치는 프레임 식별 및 원본 추출 도구의 메타데이터다. 작품은 원본 아틀라스를 요청하지 않는다. `quality-originals.json`은 과거 생성 거절 사진의 제외 목록이며 원본 재생 예외가 아니다. 일정과 드래그 예비 후보는 두 버전에서 동일한 사진 ID를 선택한다.

## 보정 전후 비교

`assets/quality-original/`의 2,972장은 Git `c8d352ef`에 남아 있던 실제 보정 전 사진을 바이트 변경 없이 복원한 것이다. 원본에 있던 누끼 흔적과 물체도 그대로 남는다. 원본 전체는 약 224MiB이지만 초기 로딩에는 포함하지 않는다. `restore-originals.py`와 원본 manifest에 출처 경로·커밋·해시를 기록한다.

원본 선택 시 현재 각도의 사진만 추가 다운로드한다. 원본은 16장씩 186개 묶음으로 배포하며 GUI에 진행률을 표시한다. 준비 중에도 기존 버전은 계속 재생되고, 준비가 끝난 시점의 같은 사진·보행 시점·편집 변환을 유지해 전환한다. 원본은 원래 프레이밍을 쓰고, 보정본은 생성 시 달라진 프레이밍의 등록 변환을 적용한다. 원본 모드에서 각도를 돌릴 때도 기존 각도를 재생하면서 새 각도를 준비한다. 원본 압축 캐시는 64MiB를 목표로 오래된 묶음을 비우되 현재 각도와 재생 구간은 보호한다.

## 재생

`reference-schedule.json`이 각도별 300틱의 사진 순서를 정한다. 25fps로 같은 착장을 3프레임씩 표시한다. `reference-sequencer.ts`는 가져온 Quaternius `Walk_Formal_Loop`의 보행 위상과 원본 관절 데이터로 순서 및 방향 전환을 선택한다. `photo-registration.ts`는 사진 전체의 크기·회전·이동만 적용한다. 관절 교환이나 팔다리 변형은 하지 않는다. 모델 파일의 라이선스와 출처는 `media/reference/`에 남긴다.

초기에 37개 각도의 보정 사진 전체를 다운로드한 뒤 첫 9개 재생 구간을 디코딩한다. 마지막 사진과 재생 준비가 끝나기 전에는 작품을 표시하지 않는다. 로딩 화면은 막대·백분율·사진 수·수신 용량만 표시하고 실패 시 재시도를 제공한다. 각도 전환 중 별도 로딩 문구는 표시하지 않는다. `quality-library.ts`는 압축 사진을 재사용하고 현재·다음 재생 구간만 디코딩한다. 빌드 시 WebP 64장씩을 바이너리 파일로 묶어 사진 요청을 2,972회에서 47회로 줄인다. 브라우저가 선택한 인코딩의 사진 바이트를 변경하지 않고, 받은 Blob을 원래 이미지 구간으로 잘라 사용한다. 전체 사진을 받은 후 시작하는 조건은 유지한다. 방향 전환 중에는 기존 시계를 유지하며 준비된 새 각도를 현재 보행 시점에 연결한다.

HTML은 `no-store`, 이미지와 JS는 콘텐츠 해시로 캐시한다. 링크에 `v=`를 붙일 필요가 없다.

## 유지보수

- `pnpm test pages/runway-walk scripts/runway-walk`: 재생·로딩·사진 무결성·전환 회귀 검사.
- `pnpm typecheck`, `pnpm build`: 타입 검사와 배포 파일 생성.
- `node scripts/runway-walk/check-motion.mjs`: 37개 각도를 각각 1,200틱 측정한다. 기존 발·몸·얼굴·출현 구간 및 전환 진행 기준을 유지한다.
- 새 사진/일정은 위 수치 검사와 실제 재생 검토를 모두 거친다. 수치 통과만으로 시각적으로 자연스럽다고 판정하지 않는다.

영상 출처와 원본 추출 설정은 `scripts/runway-walk/angle-sources.json`, `angle-shots.json`에 있다. 현재 작품과 관계없는 초기 합성·생성 배치·검토 서버 코드는 정리했다. 자세/각도 생성 실험을 다시 시작하려면 최종 작품과 분리한다.

## 이전 재생 사진 압축 기록

`python3 scripts/runway-walk/compress-quality.py`는 최종 WebP를 quality 80 / method 4로 한 번 압축한다. 이미지 해상도를 줄이지 않으며 모든 사진의 알파 값과 크기를 원본과 대조한다. 더 커지는 결과는 기존 파일을 유지한다. 전체 결과를 검증한 뒤 재생 파일과 manifest 해시를 갱신한다. 같은 설정을 다시 실행하면 압축을 생략해 반복 손실을 방지한다. 압축 설정과 전후 용량은 manifest의 `compression`에 기록한다. 색상·질감에는 손실 압축 차이가 생길 수 있으며, 이전 재생 파일은 Git 이력에서 복원할 수 있다.

묶음 파일은 `scripts/runway-walk/quality-packs.ts`가 빌드 시 생성한다. 개별 이미지 파일은 편집용 소스로 유지하고 배포에는 묶음만 포함한다. 묶음 파일의 내용 해시로 캐시하며 길이·구간 인덱스를 검증한 뒤 디코딩한다. 실패하면 해당 묶음만 재시도한다. 로딩 진행 집계는 사진 배열을 매번 순회하지 않고 완료한 사진 수와 바이트를 누적한다.

## AVIF 용량 최적화

`python3 scripts/runway-walk/encode-avif.py --width 640`는 같은 입력에서 640×960 AVIF와 WebP를 함께 만든다. `avifenc`(libavif)와 Pillow가 필요하다. 표시 비율 2:3을 유지해 Lanczos로 축소한다. AVIF는 색상 품질 50·4:4:4, WebP는 품질 80·method 4다. 투명도는 8단위로 정리한 뒤 무손실로 저장하며 각 사진의 축소 입력 대비 알파 오차가 4/255 이하인지 검증한다. 축소 입력에서 완전히 투명하거나 불투명한 값은 이 정리 중 유지한다. 색상에는 손실 압축 차이가 있을 수 있다.

이미 압축하기 전의 사진을 Git에서 사용할 수 있으면 `--source-ref REF`로 입력해 반복 RGB 압축을 피할 수 있다. 물체 제거 사진은 `--cleanup-ref REF`로 삭제가 반영된 고해상도 버전을 지정한다. 지정하지 않으면 현재 수정본을 쓴다. 전체 결과를 캐시에 준비하고 크기·알파·해시를 검증한 뒤 두 형식의 파일과 manifest를 교체한다. 생성 영수증과 입력/결과 해시를 캐시에 기록하며 동일 입력·설정은 다시 인코딩하지 않는다. 파생 manifest는 현재 WebP의 해시도 연결해 오래된 파일이 배포되는 것을 막는다.

브라우저는 네트워크 요청이 없는 작은 AVIF 디코딩 시험 후 한 가지 형식만 내려받는다. 두 형식을 모두 받지 않는다. AVIF와 WebP는 각각 47개 묶음이며, 전체 각도의 준비가 끝난 뒤 재생한다. 두 형식 모두 640×960이며 전체 이미지 배치는 동일하다. 캔버스도 이미지의 실제 해상도를 사용해 불필요한 확대와 픽셀 처리를 줄인다. 0° 흰 지팡이 모양 물체의 제거 단계에서는 9장 모두 해당 영역만 삭제해 인물 RGB·얼굴·발 픽셀을 유지했으며, 축소본은 이 삭제가 반영된 입력에서 만든다. 제거 도구 결과의 해시·프롬프트와 적용 영역은 provenance에 기록한다.

현재 전달 해상도는 두 형식 모두 640×960이다. 이미지 총량은 AVIF 약 79.0MiB, WebP 약 110.8MiB이며 고해상도 입력과 이전 전달 파일은 Git/캐시에서 보존한다. 768·640·576px의 휴대폰 표시 크기 및 얼굴/옷감 확대 샘플 비교 후 640px을 선택했다. 실제 휴대폰의 체감 품질·성능 측정과는 구별한다.
